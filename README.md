A kernel and a UEFI bootloader written from scratch.

# Info
I don't have an end goal with this OS. This project is just for tinkering with
osdev and to see what goes in making an OS from scratch. I might add or remove
anything from it, whatever feels interesting.

The most recent additions are support for booting multiple CPU cores and
doing heap allocation. A few important things are still missing before it becomes
a proper playground of OSDev ideas.

But before trying to add any other features I will be doing some necessary code
cleanup and fix some important problems before they become big. Currently it
only works on 32-bit x86 architecture, has no seperation between normal kernel
code and architecture spcecific code, works only inside `qemu-system-i386`,
makes use of a lot of hardcoded assumptions about the architecture and is
riddled with undocumented `unsafe` usages.

So before adding anything new, the following needs to happen:

- Port to x64 and then to ARM64
  
  This will help me identify normal kernel code and architecture specific code
  so that they could be kept seperate.

- More robust way of doing what it already does.

...code cleanup and better documentation.

## Boot Process
1) UEFI bootloader starts

2) It looks for console/serial logging protocols and the kernel
   executable(an ELF file).

3) Get the system memory map, call `ExitBootServices` and take over physical
   memory allocation.

3) Parse the kernel elf file for loadable segments, allocate frames for them.

4) Create the page table map and enable paging. Different regions get either
   identity mapped or get some dynamic virtual address.

5) Prepare the stack for the kernel bootstrap processor(BSP), fill it with 
   necessary arguments and jump to kernel entry point.

6) The kernel then sets up its own serial logging, takes the physical memory
   description it got from the bootloader and creates its own, more detailed copy
   of the physical memory description.

7) It then divides the available virtual address space among different cores,
   sets up stack for each available cpu core and initializes them one by one.

8) The bootstrap processor and all other cores then set up their private heaps
   in their part of the virtual address space.

   Right now there is no truly global allocator. Each core has its own single
   threaded malloc like allocator which allocates memory only in the core's
   reserved virtual address space. All the cores currently share the page table
   mappings, but each one of them has its own private heap. Due to the shared
   paging structures they can technically see each other's mappings, but
   eventually each core will have its own copy of paging structures. Although I
   will keep one shared heap which will be common across all cores. This will
   not be a "no shared memory" OS, but a "limited shared memory" one.

9) All the cores then jump to a common starting point, the true 'main' function.

For more details, read the commit messages or may be the code itself;)

# Building/Running

## No Linker Scripts
This does not requires any linker script trickery. Both the kernel and the
bootloader are generated by the Rust compiler as individual statically linked
binaries.

The kernel is a freestanding ELF executable of some target
architecture(currently x86 only) and the bootloader is a PE32+ executable of
the appropriate architecture. Both are statically compiled and have no external
3rd party dependencies.

The kernel requires some externally assembled x86 assembly code like the files
`irq.asm` and `isr.asm` which are build using NASM which then get linked by the
Rust compiler.

Some helper bash scripts are provided which put the kernel and the bootloader
in appropriate disk images for use with QEMU, which has its own helper scripts.
So preferably run it on linux.

There are helper `just` commands to do various tasks.

## Requirements
- Rust nightly toolchain
- NASM assembler
- Just, the command runner
- QEMU, specifically qemu-system-i386

## `Just` commands for building and running.
- `just full` to rebuild the kernel plus bootloader and run them.
- `just build` to build both the kernel and the bootloader.
- `just run` to only run the kernel plus bootloader, without building then again.
   Before using this, use `just build` at least once.
- `just kernel` to build the kernel only.
- `just uefi` to build the bootloader only.
